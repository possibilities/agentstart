# 0048: Share the in-place Devin snapshot across concurrent sessions and project config

Accepted September 26, 2026. Supersedes [ADR 0047](0047-run-terminal-devin-in-place-with-cleanup.md)'s single-invocation claim and foreign-`.devin` refusal; preserves its in-place snapshot, process-identity cleanup, pass-through, and exact-marker verification.

Devin's only project config location is `.devin` at the Git root, so ADR 0047's per-root record lock made a second terminal `devin` in one checkout fail, and any pre-existing `.devin` — a project's own config or a stale snapshot the cleanup had not reached — made it refuse to run at all. Invocation records are now one per launch (`<sha256-of-root>-<invocation-id>.json`), and every record names the snapshot generation it joined. Sessions that find a canonical AgentStart marker join it without rewriting files; sessions that find an unmarked `.devin` merge the snapshot beside project content, writing only missing or byte-identical files, rendering a `.gitignore` that covers only claimed entries, and warning on stderr for each kept conflict. Non-directory `.devin` and foreign or malformed markers still refuse.

The cleanup groups records by Git root and reconciles a root only after every record's wrapper and child identities have ended, deleting unchanged files across the union of the group's manifests and preserving edits and foreign content as before. Records that died before writing a manifest keep the wholesale staging removal only when they created the directory; merged records limit it to the verified marker. Single-generation `<sha256>.json` records from the previous format still reconcile under the same rules.
